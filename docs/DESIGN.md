# 설계 문서

## 화면 구성

| 화면 | 경로 | 누가 | 하는 일 |
|---|---|---|---|
| 홈 | `#/` | 전임자 | 서비스 소개, 내가 만든 인수인계 목록 |
| 새 인수인계 | `#/new` | 전임자 | ① 기본 정보 → ② 메일·파일 목록 넣기 → ③ 분석에서 뺄 것 고르기 → ④ 분석 |
| 검토 | `#/h/:id` | 전임자 | 카드 수정·삭제·추가·병합, 확정 후 공유 링크, 후임자 질문에 답변 |
| 후임자 | `#/s/:token` | 후임자 | 업무별 "확인함 / 질문 있음", 질문 남기기, 진행률 |

```
검토 화면
┌───────────────────────────────────────────────────────────┐
│ 제목                                          [검토 중]   │
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ │
│ 9 찾은 업무   46 메일   74 파일   3 답장 안 한 업무         │
├───────────────────────────────────────────────────────────┤
│ 안내문                [업무 추가] [합치기] [확정하기]       │
├──────────────┬────────────────────────────────────────────┤
│ 진행 중 ▌    │ ▌ 업무명                       [수정][삭제] │
│  ㄴ 카드      │ ▌ 상태  주기  분류  근거 수준               │
│ 정기 ▌       │ ▌ 설명                                      │
│  ㄴ 카드      │ ▌ ▒주의사항(형광펜)▒                        │
│ 참고 ▌       │ ▌ 관련 파일        │ 관련 담당자             │
│ 완료 ▌       │ ▌ 근거: ▒메일 제목▒  ▒파일 경로▒            │
│ 연락처       │                                            │
└──────────────┴────────────────────────────────────────────┘
```

디자인 원칙
- "인수인계 장부"라는 은유: 왼쪽은 바인더 색인 탭, 오른쪽 카드는 장부의 한 장.
- 상태 색(진행 중 보라, 정기 초록, 참고 회색, 완료 연회색)은 색인 탭과 카드 왼쪽 가장자리에만 쓴다.
- 형광펜 노랑은 **근거와 주의사항에만** 쓴다. 노란색이 보이면 "확인해야 할 것"이라는 뜻.

## 데이터 구조 (ERD)

```
handover 1 ──< card 1 ──< comment
    │
    └────< contact
```

| 테이블 | 주요 열 | 설명 |
|---|---|---|
| `handover` | id, title, owner_name, owner_email, successor_name, status(draft/confirmed), share_token, stats(JSON), created_at, confirmed_at | 인수인계 한 건 |
| `card` | id, handover_id, position, title, description, cycle, status, category, related_files(JSON), related_people(JSON), caution, evidence(JSON), evidence_total, confidence, needs_reply, successor_state | 업무 하나 |
| `contact` | id, handover_id, name, email, org, internal, count | 업무 연락처 |
| `comment` | id, card_id, author(predecessor/successor), body, created_at | 후임자 질문과 전임자 답변 |

**저장하지 않는 것**: 업로드한 메일 원본, 메일 본문 전체, 파일 목록 원본. 카드 설명에 들어가는
"마지막 내용"은 인용·서명을 뗀 앞부분 90자이며 전화번호·주민번호·카드번호·이메일을 가린 뒤 저장한다.

## 분석 규칙

| 단계 | 규칙 | 결과 |
|---|---|---|
| 주제 묶기 | 제목에서 RE/FW, `[태그]`, 날짜(10월, 4주차, Q3, 2026_10 등)를 지운 뒤 같은 제목끼리 묶는다 | 업무 후보 |
| 반복 업무 | RE/FW가 아닌 **새로 시작한 메일**이 3일 이상 서로 다른 날에 있고, 간격의 중앙값이 7일 근처면 매주, 30일 근처면 매월, 90일 근처면 분기. 요청 직후 2~3일 안의 회신은 한 번으로 친다 | `정기` 카드 |
| 진행 중 | 반복 업무가 아닌 스레드(메일 2건 이상) 중 마지막 메일이 기준일 14일 안이거나 관련 폴더에 최근 수정 파일이 있으면 진행 중, 아니면 완료 | `진행 중` / `완료` 카드 |
| 답장 필요 | 최근 14일 안의 마지막 메일을 내가 아닌 사람이 보냄 | 빨간 표시 |
| 파일 반복 산출물 | 같은 폴더·같은 기본 이름(날짜·버전 표시 제외) 파일이 3개 이상이고 파일명에 주차/월/분기 표시가 있음 | 이미 있는 카드에 붙이거나 새 `정기` 카드 |
| 핵심 문서 | `_v2`, `_최종`, `_수정본` 같은 버전 파일이 2개 이상 | 해당 카드의 맨 앞 파일로 올리고 근거에 표시 |
| 교차 분석 | 첨부파일 이름 ↔ 폴더 파일 이름, 스레드 제목 ↔ 폴더 이름(예: "사무실 이전" ↔ `04_프로젝트/사무실이전`) | 카드에 관련 파일 연결 |
| 양식 | `양식`·`템플릿` 폴더의 파일은 이름이 겹치는 카드에 붙이고, 남는 것은 "자주 쓰는 양식 파일" 카드로 | `참고` 카드 |
| 신뢰도 | 반복 횟수, 메일 근거, 파일 근거가 많을수록 높음 | 근거 충분 / 보통 / 적음 |

"기준일"은 오늘이 아니라 **데이터 안의 가장 늦은 날짜**다. 퇴사 직전에 내보낸 데이터를 나중에 분석해도 결과가 같다.
